# Landwu 手机做单工作台设计

## 目标

APK 继续复用 Landwu WebView 登录态，但登录成功后用全屏工作台覆盖后台页面。用户只接触待编辑、待付款、成分尺码、在线验图和 JIT 支付环节；不处理已支付订单，也不下载图片。

## 订单流程

工作台同时读取状态 1 的待编辑订单和状态 2 的待付款订单，并显示待编辑总数、JIT、VMI 和待付款总数。推进操作只处理 JIT：

1. 读取 JIT 平台标签并按平台分组。
2. 为每个平台查找 TEMU 物流。
3. 调用物流预检接口，任一分组未全量通过时不提交任何订单。
4. 逐单提交改物流，显示当前订单和完成进度。
5. 轮询待付款列表，完成后自动切换到待付款页。

VMI 只显示数量和明细，不参与改物流。

## 成分尺码

待付款页展示全部 JIT 和 VMI SKU。云端成分库按 SKC_ID、SPU_ID、SKU 依次匹配，支持一键修改所有有效建议，也保留逐项手动修改。批量任务逐项显示成功或失败，不因单项失败停止剩余任务。

成分库下载与订单刷新并行，下载失败不影响订单读取或手动修改。成功下载后写入 WebView 的 IndexedDB，后续网络失败时使用本机缓存。

## 在线验图

待付款 SKU 从订单及编辑详情响应中收集并去重图片链接。卡片内直接显示接近整行宽的大图，使用完整比例避免裁切；多图横向滑动，点图可进入全屏预览。没有可用图链时显示空状态，不阻塞尺码修改或支付预检。

## 支付

支付只处理当前待付款 JIT，VMI 始终排除。用户确认后，工作台重新读取待付款 JIT 并校验订单范围，调用 `/order/getCheckOrder` 预检；返回为空、出现风险字段或未覆盖预期订单时停止。预检通过后再次校验订单范围，最后调用 `/order/orderPay`。“通用尺码”不自动阻断，但必须在确认框中显著警告。

## 交互与错误处理

界面采用手机全屏工作台，顶部固定显示四项数量，主区用待编辑和待付款两个页签。真实改物流、修改尺码和支付前都需要确认。运行中的按钮禁用，操作区显示明确的当前步骤、进度和结果；网络错误、登录失效和接口错误直接显示可读提示。

## APK 结构

Android 应用只负责承载 WebView、打开 Landwu 并注入构建时内置的 `assets/landwu-mobile.user.js`。`mobile/android/build_apk.ps1` 从当前带版本号的 userscript 复制该资源，因此发布时必须同步脚本版本、构建来源和 Android manifest 版本。APK 输出位于 `mobile/android/build/outputs/`，由 `.gitignore` 排除。

## 验证

- JavaScript 语法检查。
- 模拟未登录、空订单、待编辑 JIT/VMI、待付款匹配、支付成功、支付预检失败和批量进度。
- 360、390 和 430 像素宽度截图检查，不允许横向溢出。
- APK 构建、签名校验和内置脚本版本检查。
